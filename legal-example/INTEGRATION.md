# INTEGRATION.md — техническое руководство для разработчика

Этот документ создан для помощи в интеграции и 
подключении  данного модуля (`acebattle-forms`) к основному сайту
**https://poland.acebattle.run/**, дорабатывать его под реальные
процессы компании и/или интегрировать с настоящей базой данных.

Если вы здесь впервые — прочитайте сначала `README.md` (что вообще
внутри, как запустить локально), а этот документ читайте, когда будете
готовы **встраивать модуль в продакшен**.

---

## 1. Что это за модуль, коротко

Next.js 14 (App Router, TypeScript, Tailwind) приложение из двух частей:

1. **Публичная часть** (`app/[lang]/...`) — многоязычные (PL/EN/UA/RU)
   формы регистрации и согласий для участников спортивных мероприятий
   ACE BATTLE RUN, с автоподстановкой даты мероприятия, даты подписания
   и данных участника прямо в текст юридических документов.
2. **Приватная часть** (`app/admin/...`) — панель администратора:
   табло всех поданных заявок, просмотр/печать подписанных документов
   (по одному и пакетно), управление календарём мероприятий, просмотр
   внутренних (не публикуемых участникам) документов.

Модуль **самодостаточен** — у него своя система переводов, свой роутинг,
свои стили. Он не обращается к API основного сайта и не знает о его
существовании. Интеграция — это **ваша** задача, и есть два разумных
пути (см. раздел 3).

## 2. Архитектура на одной странице

```
┌─────────────────────────────────────────────────────────────┐
│  ПОСЕТИТЕЛЬ САЙТА                                            │
│  /{lang}                → хаб: карточки документов + вкладки │
│                            "Bieg indywidualny" / "TEAM MILE" │
│  /{lang}/register        → единая форма регистрации          │
│  /{lang}/documents/[doc]/read  → полный текст документа      │
│  /{lang}/appendix/[doc]  → полный текст Załącznika (только   │
│                            для серии TEAM MILE, только для   │
│                            чтения, без подписи)               │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼  POST /api/register
┌─────────────────────────────────────────────────────────────┐
│  lib/submissions-store.ts  →  .data/submissions.json         │
│  (dev-хранилище — см. раздел 5, ЗАМЕНИТЬ на БД перед продом) │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  АДМИНИСТРАТОР (за /admin, защищено кодом доступа)           │
│  /admin                  → табло заявок, чекбоксы, bulk-печать│
│  /admin/submissions/[id] → одна заявка: все документы,       │
│                            заполненные данными, для печати   │
│  /admin/submissions/print→ печать НЕСКОЛЬКИХ заявок сразу    │
│  /admin/events           → добавление новых дат мероприятий  │
│  /admin/documents/[doc]  → внутренние документы (LIA,        │
│                            Potwierdzenie, Provisions on the  │
│                            Team Captain, Załącznik 2)         │
└─────────────────────────────────────────────────────────────┘
```

**Ключевая идея модели данных:** одно мероприятие (`EventRecord`) — это
один конкретный день забега. Несколько дней одной серии (например,
TEAM MILE POLAND: 22.09, 01.10, 10.10.2026) объединены общим
`seriesId`/`seriesName`, но остаются отдельными записями — участник
выбирает конкретный день, документы и логика формы общие для всей серии
через `eventType` (`lib/types.ts`).

## 3. Два пути интеграции с poland.acebattle.run

### Вариант А — отдельный поддомен или под-путь (рекомендуется для старта)

Разверните этот модуль **как отдельное Next.js-приложение**, например на
`forms.acebattle.run` или `poland.acebattle.run/forms`, и со основного
сайта сделайте обычные `<a href="https://forms.acebattle.run/pl">`
ссылки на кнопки «Zarejestruj się», «Regulamin i warunki» и т.п.

**Плюсы:** нулевой риск конфликтов версий React/Next/Tailwind с основным
сайтом, деплой и откат независимы, можно выкатить сегодня.
**Минусы:** два деплоя вместо одного, шапка/подвал модуля должны
визуально совпадать с основным сайтом вручную (см. раздел 8).

Шаги:
1. `npm install && npm run build` в этой папке — если собирается без
   ошибок, godny to hostować bez zmian.
2. Задеплойте как обычное Next.js-приложение (Vercel/собственный сервер
   с `next start`/Docker — см. `next.config.mjs`, изменений не требует).
3. Настройте DNS/поддомен и переменные окружения (раздел 6).
4. С основного сайта проставьте ссылки на `/{lang}/register` для нужных
   мероприятий (можно передавать `?event=ID` заранее, если знаете ID
   нужного дня — см. `lib/events.ts`).

### Вариант Б — слияние в существующий репозиторий poland.acebattle.run

Если у основного сайта тоже Next.js 14 App Router с похожей структурой
(`app/[lang]/...`), можно физически влить код:

1. **Скопируйте без изменений** (эти папки самодостаточны, без внешних
   импортов из остального сайта):
   - `app/[lang]/register/`, `app/[lang]/documents/`, `app/[lang]/appendix/`
   - `app/admin/`
   - `app/api/register/`, `app/api/consent/`, `app/api/admin/`, `app/api/events/`
   - `components/`, `content/`, `lib/`
2. **Слейте вручную** (это точки конфликта, готовых скриптов для
   автослияния нет):
   - `middleware.ts` — если у основного сайта уже есть свой мидлвар,
     объедините логику (наш файл разделяет проверку `/admin/*` и
     определение языка для остального сайта — оба блока хорошо
     закомментированы, переносите как отдельные `if`-ветки).
   - `tailwind.config.ts` — перенесите только `theme.extend.colors.brand.*`
     и `theme.extend.fontFamily` в существующий конфиг, а не файл целиком.
   - `app/layout.tsx` — если у сайта уже есть корневой layout со своими
     шрифтами/`<html>`/`<body>`, перенесите только импорт `globals.css`
     и, если нужно, шрифты Oswald/Inter (см. раздел 8).
   - `app/globals.css` — либо замените, либо влейте секции
     `.legal-prose`, `.card`, `.btn-primary`, `.field-input` и блок
     `@media print` в конец существующего файла (это все кастомные
     классы, специфичные для этого модуля — конфликтов имён с
     Tailwind-утилитами не будет).
3. Проверьте, что в `package.json` основного сайта уже есть **zod**
   (используется для валидации форм) — если нет, добавьте
   (`npm install zod`).
4. Прогоните `npm run build` в объединённом репозитории и устраните
   конфликты путей, если основной сайт уже занимает `/register` или
   `/admin` под что-то своё (переименуйте один из них).

**Какой вариант выбрать?** Если нужно быстро протестировать с реальными
участниками — вариант А. Если это финальная цель и есть время на
аккуратное слияние — вариант Б.

## 4. Карта всех маршрутов

### Публичные (для участника)

| Маршрут | Назначение |
|---|---|
| `/{lang}` | Хаб документов, вкладки типа мероприятия |
| `/{lang}/register?event={id}` | Единая форма регистрации |
| `/{lang}/documents/{doc}/read?event={id}` | Полный текст документа (только чтение) |
| `/{lang}/appendix/{doc}?event={id}` | Полный текст Załącznika серии TEAM MILE (только чтение) |

`{lang}` ∈ `pl`, `en`, `ua`, `ru`. `{doc}` — см. `DocumentSlug` /
`PUBLIC_APPENDIX_SLUGS` в `lib/types.ts`.

### API (используются формами, JSON)

| Маршрут | Метод | Назначение |
|---|---|---|
| `/api/events` | GET | Список всех мероприятий (встроенные + добавленные админом) |
| `/api/events/{id}` | GET | Одно мероприятие |
| `/api/register` | POST | Приём единой формы регистрации |
| `/api/consent` | POST | Устаревший эндпоинт для отдельных документов — оставлен для совместимости, новый фронтенд им не пользуется |

### Административные (защищены кодом доступа, см. раздел 7)

| Маршрут | Назначение |
|---|---|
| `/admin` | Табло заявок, выбор нескольких строк, «Drukuj wybrane» |
| `/admin/submissions/{id}` | Одна заявка целиком: данные, чекбоксы, все документы с подставленными токенами; переключатель языка печати |
| `/admin/submissions/print?ids=id1,id2,...&lang=` | Печать/PDF нескольких заявок за один проход; без `lang` — каждая заявка на своём языке |
| `/admin/events` | Просмотр серий и дней, форма добавления новой даты |
| `/admin/documents/{doc}` | Внутренние документы: LIA, Potwierdzenie, Provisions on the Team Captain, Załącznik 2 |
| `/admin/login` | Вход по коду доступа |

## 5. Что нужно заменить перед продакшеном (обязательно)

Всё, что ниже — файловое/dev-хранилище, специально спроектированное так,
чтобы **сигнатуры функций не менялись** после подключения настоящей БД —
остальной код (компоненты, API-роуты) их не касается.

### 5.1. Заявки участников — `lib/submissions-store.ts`

Сейчас пишет в `.data/submissions.json`. Замените реализацию функций
`appendSubmission`, `readAllSubmissions`, `getSubmissionById`,
`listSubmissionsSorted` на запросы к вашей БД (Postgres/Supabase/Prisma),
сохранив те же имена и типы (`StoredSubmission` в том же файле).

**Почему это критично:** на serverless-хостингах (Vercel и подобные)
файловая система эфемерна — данные участников могут потеряться между
деплоями/запросами.

### 5.2. Календарь мероприятий — `lib/events.ts` + `lib/events-store.ts`

`lib/events.ts` содержит массив `BUILT_IN_EVENTS` (захардкоженные
мероприятия) и функцию `listEvents()`, которая объединяет его с
данными из `lib/events-store.ts` (`.data/events.json` — даты, добавленные
через `/admin/events`). Для продакшена:

- Либо замените `BUILT_IN_EVENTS` на запрос к вашей CMS/БД мероприятий
  и уберите `events-store.ts` совсем (если календарь будет вестись в
  основной системе сайта);
- Либо, если хотите оставить **этот** модуль источником истины для
  расписания — просто замените файловое хранилище в `events-store.ts`
  на БД, как в п. 5.1, оставив UI `/admin/events` как есть.

Контракт `EventRecord` (форма объекта) описан и прокомментирован в
`lib/types.ts` — не меняйте поля без необходимости, это сломает формы.

### 5.3. Доступ к панели администратора — `lib/admin-auth.ts`

Сейчас — один общий код доступа (`ADMIN_ACCESS_CODE` в `.env`),
подходит только для тестов и маленькой команды: нет персональных
учётных записей, нет ролей (администратор/менеджер), нет журнала «кто
заходил». **Перед реальным использованием с персональными данными
участников замените на полноценную аутентификацию**, например:

- [NextAuth.js](https://next-auth.js.org/) с провайдером email/пароль
  или SSO вашей компании;
- проверку прав в `middleware.ts` (сейчас там `isValidAdminSessionValue`
  — замените эту функцию на проверку сессии/JWT из вашей auth-системы).

## 6. Переменные окружения

Скопируйте `.env.example` → `.env.local` и заполните:

```env
# Код доступа к /admin. БЕЗ этой переменной панель полностью
# заблокирована для всех (безопасное поведение по умолчанию).
ADMIN_ACCESS_CODE=замените-на-длинный-случайный-код

# (опционально) Если API мероприятий должно ходить не в мок,
# а во внешний сервис — базовый URL этого сервиса.
NEXT_PUBLIC_EVENTS_API_BASE=

# (опционально) Вебхук, на который дублируются все новые заявки
# (например, в Google Sheets/CRM через Zapier/Make) — помимо записи
# в основное хранилище.
CONSENT_STORAGE_WEBHOOK_URL=

# (опционально) Простая защита /api/consent от чужих запросов.
CONSENT_API_TOKEN=
```

## 7. Панель администратора — что важно знать

- **Язык интерфейса панели — всегда польский** (это осознанное решение:
  предполагается, что администраторы/организаторы — польскоязычный
  персонал). Язык **печатаемых документов** — язык, на котором участник
  заполнял форму (`submission.locale`), с ручным переключателем прямо на
  странице заявки (кнопки PL/EN/UA/RU над областью печати) — администратор
  всегда может распечатать копию на любом из 4 языков независимо от
  того, на каком языке регистрировался участник.
- **Массовая печать**: на `/admin` отметьте чекбоксы нужных заявок →
  кнопка «Drukuj wybrane» → откроется `/admin/submissions/print` со
  всеми выбранными документами подряд (каждый со своим `page-break`)
  → Ctrl+P / кнопка печати → «Сохранить как PDF» в диалоге браузера даст
  один PDF-файл со всеми заявками.
- **Załącznik 2** (расписание для организаторов) сознательно НЕ
  показывается участникам нигде на публичном сайте — он только в
  `/admin/documents/team-appendix2`. Если понадобится добавить ещё
  внутренний документ такого рода — добавляйте его в
  `TEAM_INTERNAL_DOCUMENT_SLUGS`, а не в `PUBLIC_APPENDIX_SLUGS`
  (оба массива — в `lib/types.ts`, с комментариями прямо на месте).

## 8. Приведение дизайна в соответствие с основным сайтом

Цвета и шрифты (`tailwind.config.ts` → `theme.extend.colors.brand`,
`app/layout.tsx` → `next/font/google` для Oswald/Inter) были подобраны
**визуально**, по скриншотам и текстовому содержимому сайта — у нас не
было прямого доступа к исходному `globals.css`/дизайн-токенам
poland.acebattle.run. Перед запуском:

1. Сверьте hex-коды в `tailwind.config.ts` (`brand.bg`, `brand.accent`,
   `brand.gold` и т.д.) с реальной палитрой сайта.
2. Сверьте шрифты — если сайт использует не Oswald/Inter, замените
   импорт в `app/layout.tsx`.
3. Логотип в `components/Header.tsx` сейчас ссылается на
   `https://poland.acebattle.run/brand/...svg` (работает уже сейчас) —
   при слиянии репозиториев (вариант Б) замените на локальный путь
   `/public`.

## 9. Как добавить новый тип мероприятия (Turniej / Liga)

Сейчас полностью укомплектованы содержимым `"individual"` и `"team"`.
Для `"tournament"`/`"league"` архитектура уже готова, не хватает только
контента. Пошагово:

1. Подготовьте документы (.docx) на 4 языках для нового формата.
2. Сконвертируйте в HTML: `pandoc -f docx -t html --wrap=none файл.docx
   -o content/legal-texts-tournament/{lang}/{doc}.html` (по образцу
   `content/legal-texts-team/`).
3. В `lib/types.ts`: добавьте слаги с префиксом `tournament-` в
   `DocumentSlug`/`InternalDocSlug`, заполните
   `DOCUMENT_SLUGS_BY_EVENT_TYPE.tournament`.
4. В `lib/legal-texts.ts`: добавьте ветку `doc.startsWith("tournament-")`
   в `resolvePath`/`resolveFallbackPath` (по образцу `"team-"`).
5. Создайте `content/i18n/tournament-{lang}.ts` по образцу
   `content/i18n/team-{lang}.ts` (документы + `internalDocuments` +
   `registerTournament`), подключите через spread в
   `content/i18n/{lang}.ts`.
6. Добавьте в `content/types.ts` поле `registerTournament` в
   `CommonDictionary`, обновите `getRegisterContent` в
   `content/dictionaries.ts`.
7. В `lib/events.ts` или через `/admin/events` создайте хотя бы одно
   мероприятие с `eventType: "tournament"` — вкладка на хабе появится
   автоматически (см. `EVENT_TYPES`/`availableTypes` в `app/[lang]/page.tsx`).

## 11. Куда смотреть при проблемах

| Симптом | Файл(ы) |
|---|---|
| Не работает вход в `/admin` | `lib/admin-auth.ts`, `.env.local` (`ADMIN_ACCESS_CODE`) |
| Мероприятие не появляется в форме | `lib/events.ts`, `lib/events-store.ts`, `.data/events.json` |
| Документ показывает не тот язык | `content/dictionaries.ts` → `getDictionary`; на печати — `content/print-labels.ts` и переключатель на `/admin/submissions/[id]` |
| Дата в тексте документа не меняется | `lib/fill-legal-template.ts` — проверьте, что нужный токен (`__EVENT_DATE__`, `__SIGN_DATE__` и т.д.) реально стоит в файле `content/legal-texts*/…/*.html` |
| Новый документ не открывается (404) | Слаг отсутствует в `DOCUMENT_SLUGS`/`PUBLIC_APPENDIX_SLUGS`/`INTERNAL_DOCUMENT_SLUGS` (`lib/types.ts`) — все публичные/read-only маршруты используют `generateStaticParams` на основе этих констант |
| Оглавление внутри документа не кликается | Значит исходный `.docx` содержал сломанное поле Word `HYPERLINK \l` — pandoc не смог его разобрать. См. историю фикса для `team-rules` (сопоставление `<a href="\l">` с реальными `id` заголовков по порядку следования) как образец, если столкнётесь с этим на новом документе |
